Onde o dashboard vai rodar?

Cada plataforma tem trade-offs diferentes para quem usa no dia a dia operacional.

A

Google Looker Studio

Conecta nativamente com Google Ads e Google Sheets. Meta via conector de terceiro. Sem código, visual drag-and-drop. Compartilhável por link.

Prós

  • Zero infraestrutura
  • Google Ads nativo
  • Fácil de atualizar

Contras

  • Salesforce via conector pago
  • Limitado em lógica customizada
  • Meta Ads menos confiável
B

Web App local (HTML + JS)

Página HTML servida localmente que chama as MCPs via Claude Code. Totalmente customizável. Você roda com um comando e abre no browser.

Prós

  • Integração direta com MCPs
  • Lógica 100% customizada
  • Sem custo de conector

Contras

  • Precisa rodar localmente
  • Mais trabalho para manter
C

Streamlit (Python)

App Python que conecta às APIs diretamente. Roda local ou faz deploy na nuvem. Gráficos interativos nativos (Plotly, Altair).

Prós

  • Python = fácil de integrar APIs
  • Gráficos ricos out-of-the-box
  • Deploy simples na nuvem

Contras

  • Precisa de Python no ambiente
  • Mais setup inicial
D

Skill Claude Code (/dashboard)

Uma nova skill que monta o relatório estruturado no terminal do Claude Code, com tabelas e métricas formatadas. Sem UI gráfica — tudo em texto rico.

Prós

  • Integração perfeita com MCPs
  • Sem infraestrutura nenhuma
  • Já no fluxo atual de trabalho

Contras

  • Sem gráficos visuais
  • Menos "dashboard" e mais "reporte"
